I’ve interviewed hundreds of people for AI roles, first as a tech lead at AWS and now for my own company. In this video I walk through a five-layer framework you can apply to pretty much any production AI system, from scoping the problem to optimizing it once it’s live. I use one of the most common interview problems as the example: an AI customer support agent for an e-commerce company that answers help center questions, looks up orders, creates tickets, and escalates to a human when it’s not sure.

The five layers are scope and assumptions, architecture, observability, production and ops, and optimization. For architecture I use a simple framework I created called KARC: what the system has to know, act on, remember, and how it all coordinates. The whole point is that every piece you add should trace back to an assumption you made about the problem. Interviewers can tell when you’re name-dropping fancy architectures without a reason.

You’ll learn how to:

Scope a problem before you touch the solution, including how much agency the system should have and how to make your assumptions explicit
Design a starting architecture with KARC, from hybrid RAG for knowledge to tool design to the four types of memory
Think through permissions, blast radius, failure handling, and trust boundaries for every tool your agent can call
Decide what to log, which evals to build on top of those logs, and which should run online as guardrails versus offline
Take a design to production by planning for scale, latency, reliability, freshness, and security
Optimize an existing system for latency, cost, quality, and specific failure patterns, and know when added complexity (like multi-agent) is actually earned
